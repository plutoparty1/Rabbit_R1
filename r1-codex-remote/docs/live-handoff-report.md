# 실시간 연결 준비 결과

현재 사용자는 이 작업 종료 후 같은 대화를 공유 서버로 이어받는 전환을 승인했습니다. 원래 대화 ID는 `01a113d7-a337-75b1-871f-d4db4a3c36b7`이며 작업 경로는 `C:\Users\정산-PC\jjs1124`입니다. 기존 PID 37572는 강제 종료하지 않았습니다.

## 확인된 범위

- 설치된 Codex 0.160.1의 인증된 loopback 공유 서버에서 두 RPC 클라이언트가 실제 새 응답의 threadId·turnId·itemId·본문을 동일하게 수신했습니다.
- 전용 시험 대화에서 PC TUI의 새 응답 `검증 숫자: 383`을 PTY 출력으로 확인했습니다. [PC 증거](pc-tui-output-proof.json)는 원래 대화 성공을 의미하지 않습니다.
- 이후 다른 새 응답 `검증 숫자: 594`을 제품 브리지가 이벤트로 받았고 공개 HTTPS/WSS 브라우저의 선택한 응답 화면에서 확인했습니다. [공개 화면 증거](live-dashboard-test.json), [화면](live-response-public-browser.png).
- 저장된 thread.turns 본문은 모니터 내용과 연결 증거로 사용하지 않습니다. PC 수신 증거는 서버 실행 ID와 해당 turnId·itemId에 묶습니다. 이전 응답 확인으로 새 응답을 증명하지 않습니다.
- 홈은 계정 잔여 한도와 세션 이름·상태를 표시합니다. 휠로 세션 목록을 넘기고 선택한 공개 응답만 펼칩니다. 진단 숫자, 도구 인자, 파일 본문, 숨겨진 사고는 이 화면에 표시하지 않습니다.

## 변경 파일

`companion/live.py`가 실제 이벤트를 구독하고 `companion/server.py`가 인증된 기기로 전달합니다. `creation/app.mjs`, `index.html`, `style.css`가 세션 목록과 응답 화면을 추가합니다. `scripts/shared_server.py`, `resume-shared.ps1`가 공유 서버와 정상 종료 후 인계를 준비합니다. `verify_live.py`, `verify_pc_tui.py` 및 관련 테스트가 시험 증거를 남깁니다.

새 실행 서버에는 모델·인증·샌드박스·승인 옵션을 덮어쓰지 않습니다. 전용 로컬 서버 토큰은 OpenAI 인증과 별개이며 QR·명령 인자에 넣지 않습니다. 외부 기기는 Codex 서버에 직접 접속하지 않습니다. 음성 원격 전송은 계속 차단합니다.

최종 점검에서 인증 파일은 초기 해시와 일치했습니다. 설정 파일은 초기 해시와 다르며 최종 수정 시각은 15:10:33, 모델 값은 `gpt-6-astra`입니다. 이 프로젝트는 설정 파일을 쓰지 않았습니다. 변경 원인은 단정하지 않았으며 기존 값을 되돌리지 않았습니다. [설정 점검](live-settings-check.json).

최종 자동 검증은 Python 32개와 PTT 시나리오 9개, Ruff, Python AST, 앱·브라우저 검사 파일의 Node 구문 검사, PowerShell 구문 분석, 패키지 의존성 검사를 통과했습니다. 로그는 [live-verification.txt](live-verification.txt)에 있습니다. 최종 검사 도구의 첫 실행에서 Windows 자식 프로세스 경로 확인이 실패했습니다. UTF-8 파이프와 절대 실행 경로를 적용한 뒤 전체 검사를 다시 실행하여 통과했으며 제품 테스트 실패로 숨기지 않았습니다.

단순화를 위해 새 의존성, 저장 이력 조회 화면, PC 전체 프로세스 감시기, 자동 음성 명령 전송은 추가하지 않았습니다. 기존 PTT와 인증·한도 조회 구조를 재사용했습니다.

## 인계와 다음 확인

1. 현재 답변이 끝난 뒤 기존 Codex 터미널에서 Ctrl+C를 두 번 눌러 정상 종료합니다. 준비된 PowerShell 창이 기존 PID의 정상 종료를 감지하고 **동일 대화 ID**를 `--remote`로 이어받습니다.
2. 이어받은 대화에서 다음 메시지를 입력합니다. 현재 답변을 생성하는 기존 TUI는 이 턴 도중 종료할 수 없으므로 이 단계는 인계 후 진행합니다.
3. `.runtime/shared-server.json`, PC의 실제 `--remote` 실행 인자, 서버의 loaded ID, 브리지에서 새로 수신한 해당 대화의 turnId·itemId·본문, PC 화면을 대조합니다. 원래 대화의 새 응답이 일치하기 전에는 연결 성공으로 표시하지 않습니다.
4. 실제로 대조한 뒤에만 `.runtime/original-live-proof.json`에 `threadId`, `endpoint`, `serverSessionId`, `turnId`, `itemId`, `pcAndBridgeEventMatched:true`를 기록합니다. 시험 대화나 저장 이력의 값으로 작성하지 않습니다.
5. 실제 r1에서 같은 응답을 확인합니다. 한국어 발화가 가능한 시점에 음성 인식·종료를 따로 검증합니다.

공유 서버에서 이미 loaded인 세션만 표시합니다. 다른 독립 실행 서버나 `--no-daemon`으로 실행 중인 Codex까지 PC 전체 세션이라고 집계하지 않습니다. 그 세션은 작업이 끝난 후 각각 공유 방식으로 이어받아야 합니다.

원래 대화 인계, 원래 대화의 PC·브리지 응답 대조, 새 화면의 실제 r1 시험, 실제 한국어 인식과 음성 자동 전송은 아직 미완료입니다. 장기 외부 주소도 없으며 승인된 임시 공개 통로는 60분 후 종료됩니다. 별도 정적 타입 검사기는 구성되지 않았습니다.

## 인계 창의 한글 수정

Windows PowerShell 5.1이 BOM 없는 UTF-8 스크립트를 기존 코드 페이지로 읽어 창 제목과 기본 작업 경로가 깨지는 문제를 발견했습니다. `scripts/resume-shared.ps1`을 UTF-8 BOM 형식으로 저장했습니다. 먼저 실패한 호환성 검사를 추가하고 인계 도구 테스트 4개·Ruff·PowerShell 구문·한글 기본 경로 검사 통과를 확인했습니다. 이전 대기 창만 정리하고 `R1 Codex 같은 대화 이어받기` 창을 다시 열었으며 원래 PID 37572는 유지했습니다.
