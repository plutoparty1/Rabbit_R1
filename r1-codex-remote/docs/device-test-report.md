# 브라우저·r1 시험 기록

기록일: 2026-10-07. 사용자는 r1 보유 및 실기 시험 가능을 확인했습니다. rabbitOS 버전은 아직 제공되지 않았습니다.

사용자가 현재 URL의 동일한 설치 QR로 이미 설치했다고 확인했습니다. 실제 r1에서 수정된 앱으로 재접속한 뒤 화면에 `WSS 수신 · Codex 연결 미증명`이 표시되었다고 확인했습니다. 이는 실제 r1의 PC 브리지 진단 snapshot 수신에 대한 사용자 확인입니다. 동일 Codex 서버·대화 연결의 증거는 아닙니다. 버튼·한국어 음성 동작은 아직 별도 검증 전입니다.

첫 연결 시도에서 `AbortSignal.timeout is not a function`이 표시되었다고 사용자가 보고했습니다. 공통 요청 함수를 수정한 뒤 실제 r1 재시험에서 WSS 수신 표시를 확인했습니다. 첫 실패와 수정 후 수신 확인을 구분하여 기록합니다.

사용자가 현재 말을 할 수 없는 상태라고 알려 한국어 실제 음성 인식 시험은 보류합니다. 발화 없이 버튼 시작·종료 이벤트와 마이크 녹음·종료만 따로 확인할 수 있습니다. 무음 녹음의 성공을 한국어 STT 통과로 판정하지 않습니다.

이후 사용자가 `최종 음성 결과 대기 시간이 초과되었습니다.`와 `SDK 시작/종료/클릭 2/2/0`, `브라우저 3/3/0`을 보고했습니다. 추가 확인에서 선택된 입력 방식은 `한국어 Web Speech (지원 확인)`이었습니다. 실제 SDK의 longPressStart·longPressEnd 수신은 사용자 확인으로 기록합니다. sideClick은 0으로 아직 미확인입니다. 이 결과는 음성 인식 모드의 종료 응답 미수신이며, 마이크 녹음 전용 모드의 실패로 판정하지 않습니다. 현재 발화할 수 없어 실제 한국어 STT 판정은 보류합니다.

Ruff 정적 검사, Node 구문 검사, PowerShell 구문 분석, Python 패키지 의존성 검사도 통과했습니다. 별도 정적 타입 검사기는 구성되지 않아 실행하지 않았습니다. Starlette는 테스트용 `httpx`에 대한 지원 종료 예정 경고를 표시하지만 테스트는 통과했습니다. 실행 차단 오류로 해석하거나 경고를 숨기지 않았습니다.

## 브라우저에서 발견하고 수정한 문제

연결 해제 후 오래된 소켓의 `onclose`가 상태 문구를 덮었습니다. 연결 세대를 갱신하여 이전 소켓 콜백을 무시하도록 수정하고 재시험했습니다. 테스트 자체의 중복 모의 API 주입도 독립 브라우저 공간에서 실행하도록 바로잡았습니다. 최종 제품 UI 시험의 JavaScript 오류는 0개입니다. 페어링 전과 해제 후 발생하는 HTTP 401은 인증 차단 시험의 예상 응답입니다.

### r1의 AbortSignal.timeout 미지원 오류

`creation/app.mjs`의 공통 `api()`는 상태 조회·페어링·통신 시험·연결 해제에서 모두 사용됩니다. 해당 함수의 최신 API 의존성을 `AbortController`·`setTimeout`으로 대체하고 `finally`에서 타이머를 해제했습니다. 응답 JSON을 읽는 동안도 8초 제한을 유지하며 시간 초과 안내는 정중한 한국어로 표시합니다. 새 패키지나 전역 polyfill을 추가하지 않았습니다.

수정 전 브라우저에서 `AbortSignal.timeout`을 제거하여 실제 기기와 동일한 오류가 발생하는 RED를 확인했습니다. 수정 후 같은 조건의 공개 HTTPS/WSS·권한 폐기 시험이 통과했습니다. 응답이 없는 요청도 8,014ms에 중단됨을 확인했습니다. 증거는 [r1-webview-compatibility-test.json](r1-webview-compatibility-test.json)에 기록했습니다. 이 파일은 PC 브라우저 재현 시험입니다. 이후 사용자가 실제 r1의 WSS 수신 표시를 별도로 확인했으며, 실기 전체 통과로 확대하지 않습니다.

참고: [MDN AbortSignal.timeout](https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal/timeout_static), [AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController). QR과 앱 주소는 그대로이며 설치한 Creation을 완전히 닫았다가 다시 열어 수정된 파일을 받습니다.

## 실제 r1에서 해야 할 순서

1. PC 진단 앱에 연결되는 신뢰 가능한 HTTPS 주소를 마련합니다. 외부 공개와 관련 설정은 승인된 범위에서만 적용합니다.
2. 공식 [QR 생성 예제](https://github.com/rabbit-hmi-oss/creations-sdk/tree/main/qr)에 제목·설명·공개 URL만 입력하여 Creation을 설치합니다. 연결 코드를 QR에 넣지 않습니다.
3. ‘시험 설정’에서 r1 실기를 선택하고 PC 터미널의 일회성 코드를 입력합니다.
4. ‘통신 시험’을 누릅니다. 실제 `HTTPS` 왕복과 `WSS 수신`, PC의 `hostId`를 확인합니다. HTTP 또는 WS 로컬 통과로 대체하지 않습니다.
5. ‘한국어 Web Speech’를 선택합니다. 오른쪽 버튼을 누르고 ‘연결 시험입니다’라고 말한 뒤 놓습니다. `SDK 시작/종료` 횟수, 최종 문장, 마이크 종료를 확인합니다.
6. STT 미지원·권한 실패이면 해당 오류를 기록합니다. ‘마이크 녹음만 확인’으로 원본 바이트 획득·종료 가능 여부를 별도로 시험합니다. 이 결과를 음성 인식 성공으로 기록하지 않습니다.
7. 무음, 취소, 앱 이탈, 네트워크 단절, 긴 누름 뒤 클릭, 녹음 제한 초과를 시험합니다. 마이크가 종료되는지 확인합니다.
8. rabbitOS 버전, 관찰한 문장, 버튼 횟수, 통신 표시, 오류를 기록합니다. 가능하면 ‘결과 저장’ 파일을 확인합니다. 다운로드가 r1에서 제공되지 않으면 화면 값을 수동으로 기록합니다.

현재 버전은 인식 문장을 화면에만 표시합니다. 자동 Codex 전송을 시험하지 않습니다. 성공 여부는 실기 증거를 받아 수동 판정합니다.

## 보류한 기능

모니터 본문·사용량·대화 선택·텍스트 제어·음성 자동 전송·영속 명령 중복 방지·장기 기기 등록은 두 핵심 연결이 증명된 다음 단계입니다. 현재 페어링은 진단용 메모리 상태이며 서버 재시작 시 폐기됩니다.
